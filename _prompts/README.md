# `_prompts/` 目录说明 · 全局编写器工作台

> 本目录存放所有用于**生成技能文件**的 AI 编写器（Writer）。所有编写器输出的 `spec.md` / `eval.md` / `examples.md` / `skill_loader.md` 均与「结构化重塑」技能保持统一文风。

---

## 📂 现有文件清单

| 文件名 | 用途 | 依赖 |
| :--- | :--- | :--- |
| `write_spec.md` | 生成 `spec.md`（技能说明书） | 只需技能名称和描述 |
| `write_eval.md` | 生成 `eval.md`（质量验收标准） | 依赖 `spec.md` 的核心原则 |
| `write_examples.md` | 生成 `examples.md`（优秀案例集） | 依赖 `spec.md` 和 `eval.md` 的实际内容 |
| `write_loader.md` | 生成 `skill_loader.md`（技能加载器） | 依赖已生成的 `prompt_vX.X.md`、`spec.md`、`eval.md`、`examples.md` |

---

## 🔁 技能文件生成顺序（不可颠倒）

当你要为一个**新技能**（如“代码审查”、“会议纪要整理”）生成全套文件时，请严格按照以下顺序执行：

| 步骤 | 调用哪个编写器 | 输入要求 | 产出文件 |
| :---: | :--- | :--- | :--- |
| 1 | `write_spec.md` | 技能名称 + 技能描述（一句话定位） | `spec.md` |
| 2 | `write_eval.md` | 技能名称 + 上一步生成的 `spec.md` 内容 | `eval.md` |
| 3 | `write_examples.md` | 技能名称 + `spec.md` 和 `eval.md` 的实际内容 | `examples.md` |
| 4 | `write_loader.md` | 技能名称 + `prompt_vX.X.md` 路径 + 前三步文件的内容摘要 | `skill_loader.md` |

> **关键原则**：每一步的输出都是下一步的输入。不能跳步，也不能并行生成。

---

## 🧩 如何扩展新的编写器？

如果你未来需要新增一种技能文件（例如 `tutorial.md` 或 `faq.md`），请按以下方式操作：

1. 在本目录下新建一个 `write_新文件类型.md`，例如 `write_tutorial.md`。
2. 该编写器的内容须遵循与现有四个编写器相同的文风规范（固定句式、固定标点、占位符列表、禁止行为）。
3. 在本 `README.md` 的“现有文件清单”和“技能文件生成顺序”中增加对应条目，明确其依赖关系（即它依赖哪些已有的文件）。
4. 新编写器生成出的文件，必须能与现有文件形成闭环（即能插入 `skill_loader.md` 的加载流程，或作为独立补充文档）。

---

## ⚠️ 使用注意事项

- **所有编写器都是独立的**：修改其中任意一个，不会影响其他编写器的运行。
- **`write_loader.md` 禁止复制其他文件的大段内容**：它只写“引用路径”和“一句话摘要”，保持轻量。
- **生成的版本号**：`spec.md` / `eval.md` / `examples.md` 的版本号必须一致（如全部 v1.0），由用户在调用时指定。
- **路径引用**：生成 `skill_loader.md` 时，必须由用户提供 `prompt_vX.X.md` 的实际相对路径（如 `../` 或 `./`），编写器不猜测。

## 📌 快速调用示例（对话模板）

> “请用 `write_spec.md` 的规则，为「[新技能名称]」生成 spec.md。技能描述：[一句话描述]。”

然后依次执行后续步骤，每次只生成一份文件，对话之间互不干扰。
