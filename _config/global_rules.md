# 全局规范

## Prompt 与 Skill 的判定标准

Prompt 与 Skill 均以 Markdown 承载，区别不在格式而在角色：**prompt 是「一次性输入」，skill 是「能力契约」**。

- **prompt 状态**：项目仅含独立的 `prompt_vX.X.md`
- **skill 状态**：项目含 `skill_vX.X.md`，且四章齐备：

| 章节 | 职责 | 对应标准 |
| :--- | :--- | :--- |
| **📥 加载说明** | 固定入口，任何会话按名字即可加载 | 可调用性 |
| **🧭 工作指令** | 行为边界与原则冲突裁决规则 | 行为契约 |
| **✅ 验收标准** | 红线二元核验 + 双向追溯 + 风险披露，输出可返工 | 可验收性 |
| **📝 提示词模板** | 可执行的模式模板 | 技能载体 |

- 前三章缺一即不得称为 skill
- 检验口径：把文件交给全新会话的 AI，能稳定产出同等质量的输出，才是 skill
- 技能文件必须**自包含**：全文粘贴进任何会话即可使用，不得依赖读取外部文件

## 命名规则

- 车间名称：中文 + "车间"后缀，如 `文本处理车间`
- 车间直接存放技能文件，不设项目子层；一个车间可容纳多个技能，技能名体现在文件名中以避免撞名
- prompt 阶段文件：`{技能名}_prompt_vX.X.md`，如 `摘要生成_prompt_v0.1.md`，版本递增改为 `v0.2`、`v1.0`
- 技能文件：`{技能名}_skill_vX.X.md`，如 `结构化重塑_skill_v1.1.md`；技能文件诞生时原 prompt 文件并入并删除
- 版本升级：文件名与标题版本号同步更改、直接改文件内容（旧版本由 git 历史承载）；技能文件无外部引用，改名零断链风险
- 个人笔记可存放 `_TODO` 前缀文件（不计入正式资产）
- 占位文件：空文件夹使用 `.gitkeep`

## 文件格式要求

- 所有文档使用 Markdown 格式
- 标题层级从 `#` 开始，不跳级
- 列表项保持统一缩进（2空格或4空格任选一种，全文一致）
- 代码块标注语言类型（如 ```markdown、```bash）

## 全局指令约定

根目录 `_prompts/` 下存放所有跨车间共享的系统级 AI 操作指令（编写器、全局迁移等），命名须明确作用域。

## 变更管理

- 任何新增、修改、删除操作必须同步记录到 `_config/changelog.md`
- changelog 按时间倒序排列，最新条目在最上方
- 每条记录包含：日期、操作类型、涉及路径、简要说明

## 注意事项

- 不要同时维护多个活跃版本：单个技能只有一个活跃文件（prompt 或 skill 二选一）
- 新建技能前请先阅读本文件，确保结构符合规范
