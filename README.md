# Lcloudy_AICraft

> 一套面向 AI 实践者的「轻量级能力演进工作区」—— 让提示词（Prompt）有家可归，让技能（Skill）有迹可循。

---

## 🎯 这是什么？

这是一个**用于系统化管理和迭代 AI 能力资产**的工作区模板。

你可以把它理解为：
- **一个文件夹即一个 AI 能力单元**（不是散落的 prompt 文件）
- **一条从 prompt → skill 的自然演进路径**（不是非此即彼）
- **一套可复用、可评估、可沉淀的技能标准**（不是一次性对话）

它不依赖任何平台或框架，纯 Markdown + 文件夹结构，开箱即用。

---

## 🧱 核心理念

```
┌─────────────────────────────────────────────────────────────┐
│  车间（场景）                                              │
│  └── 项目（具体任务）                                      │
│       ├── prompt_v0.1.md      ← 当前可用提示词            │
│       └── _skill_evolution/   ← 通向技能化的演进材料       │
│            ├── spec.md        ← 技能说明书                │
│            ├── eval.md        ← 质检标准（定量评分）       │
│            ├── examples.md    ← 优秀案例 + 验收对照        │
│            └── skill_loader.md ← 一键加载入口              │
└─────────────────────────────────────────────────────────────┘
```

**演化逻辑**：同一个项目，从一段可用的 prompt 开始，逐步补齐 spec/eval/examples，即可将“一次性提示词”升级为“可复用的标准化技能”。

## 🚀 如何使用这个仓库？

### 场景一：我想用现成的技能

1. 找到对应车间的项目文件夹（如 `文本处理车间/结构化重塑/`）
2. 把 `_skill_evolution/skill_loader.md` 的内容发给 AI
3. 按 loader 指示操作即可

### 场景二：我想把已有的 prompt 升级为 skill

1. 确保 prompt 文件已存在（如 `prompt_v0.1.md`）
2. 在 `_prompts/` 中找到对应的编写器
3. 按顺序依次生成：
   - `write_spec.md` → `spec.md`
   - `write_eval.md` → `eval.md`
   - `write_examples.md` → `examples.md`
   - `write_loader.md` → `skill_loader.md`

> 详细顺序请参考 `_prompts/README.md`

### 场景三：我想创建全新的技能

1. 在合适的车间下新建项目文件夹
2. 写入第一版 `prompt_v0.1.md`
3. 用场景二的方式逐步补齐 `_skill_evolution/`
4. 在 `_config/changelog.md` 中记录本次新增

## 🧩 设计原则

| 原则 | 说明 |
| :--- | :--- |
| **场景优先** | 按业务场景而非技术类型组织内容 |
| **渐进演进** | prompt → skill，不急于一蹴而就 |
| **格式统一** | 所有技能文件共享同一种文风和结构 |
| **模块隔离** | 车间之间、项目之间互不依赖，可独立增删 |
| **人工可读** | 纯 Markdown，无需任何工具即可浏览和编辑 |
